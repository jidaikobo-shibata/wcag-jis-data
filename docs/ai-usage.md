# AIでの活用

このデータセットは、AIがWCAGの番号、版、名称、本文、出典を取り違えずに参照するための資料です。質問への回答や報告書の下書きに利用できます。個々のウェブページに達成基準が適用されるか、適合しているかを判断する規則や試験結果は含みません。

## まず番号で参照する

達成基準番号が分かっているときは、次のコマンドを使います。初回の依存ライブラリの導入は[メンテナンスガイド](maintenance.md#準備)を参照してください。

```bash
.venv/bin/python tools/show_criterion.py 2.4.6
.venv/bin/python tools/show_criterion.py 2.4.6 --format json
```

JSONには、各版の `key`、`status`、`level`、名称、本文、`source_ref`、版間の関係、日英解説書のURLが含まれます。`2.4.6` のような番号だけで複数の版を一緒に取得できるので、AIへの入力として使いやすくなります。大量の項目を一度にプロンプトへ貼る必要はありません。

必要な版と言語が決まっている場合は、短いJSONを出力できます。`--edition` には `wcag:2.2`、`wcag:2.1`、`wcag:2.0`、`jis-x-8341-3:2016` のいずれかを指定します。

```bash
.venv/bin/python tools/show_criterion.py 2.4.6 \
  --format compact-json \
  --edition wcag:2.2 \
  --language ja
```

この形式には、指定版の状態とレベル、指定言語の名称・本文、それぞれの出典、利用条件に関係する出典情報を含めます。版間の関係と解説書一覧は省きます。名称や本文が収録されていないときは空配列になります。空配列を「基準が存在しない」「適用されない」と読み替えないでください。指定版に達成基準が存在しない場合はエラーになります。

## 番号が分からない質問を検索する

RAGを作る場合、検索対象は `data/items.json`、`names.json`、`texts.json` から組み立てます。`item_key` ごとに1件の検索単位を作り、名称と本文を検索対象に、次の情報をメタデータとして残すと扱いやすくなります。

| 項目 | 用途 |
| --- | --- |
| `item_key`、`number`、`standard`、`edition` | 番号と版の混同を防ぐ |
| `kind`、`status`、`level` | 原則・ガイドライン・達成基準の区別、廃止状態、レベルの確認 |
| `language`、名称の `status` | 英語原文、WAIC参考訳、旧訳、手元資料の区別 |
| `source_id`、`source_ref` | 原文に戻り、回答に出典を付ける。手元資料由来の名称にはURLがない場合もある |

番号らしい文字列が質問にある場合は、意味検索より先に番号で絞り込みます。番号がない場合は、日英の名称や本文から候補を探し、候補の番号を `show_criterion.py` で再取得してから回答を作ります。検索順位だけで版や名称の正しさを決めないでください。

`data/relations.json` は番号を介した版間の関係を示しますが、本文の同一性は示しません。WCAG 2.2の `4.1.1` は廃止項目として残っています。現行の達成基準として扱わないでください。

解説書は `data/understanding/wcag22/documents.json` で項目と対応しています。解説書は理解を助ける資料であり、規範的な達成基準本文とは区別します。HTMLをAIに読ませる場合も、収録ファイルのパスと元ページのURLを一緒に渡してください。

## 業務での使い分け

- **達成基準の説明**：番号でJSONを取得し、WCAG 2.2の英語本文とWAIC参考訳、解説書のURLを渡します。名称の変遷が必要なときだけ旧版の情報も使います。
- **報告書の下書き**：規格の情報とは別に、実際のページで観察した事実、試験条件、人が判断した結果を渡します。AIには事実と規格の根拠を対応付けさせ、未確認の事項は未確認のまま残します。
- **適用可能性の検討**：ページ上の画像や動画などを調べて候補の達成基準を挙げる場合、このデータセットから基準の本文を参照できます。ただし、要素があるだけで適用や不適合を確定せず、条件と例外を人が確認します。

これらをRAGに実装するときも、検索で得た文書の `source_ref` と、ページ調査で得た証拠を別のフィールドに保持すると、回答の根拠を追いやすくなります。

## 回答時の確認事項

1. 対象の規格と版を明記する。WCAG 2.2の英語原文を正式版として扱い、WAIC日本語訳を参考訳と示す。
2. 名称や本文の `source_ref` を出典として示す。日本語本文の断片を再掲するときは、[WAICの利用条件](https://waic.jp/license-for-translated-documents/)に沿う表示を付ける。
3. JIS X 8341-3:2016の本文は収録されていない。JIS名称は手元資料由来で、公開条件と正式文書との照合が未完了であることを示す。
4. データにない説明、適用条件、試験結果を補って断定しない。ウェブページの評価では、実際のページから得た証拠と人の判断を分けて示す。

AIに入力した本文を外部サービスで保存・索引化・再配布する場合は、[権利表示と出典](../THIRD_PARTY_NOTICES.md)を確認してください。MITライセンスは収録されたW3C・WAIC由来の文章には適用されません。

## Codexなどへの指示例

プロジェクトで作業するAIには、次の指示を渡せます。作業先の `AGENTS.md` に加える場合も、参照先はこのリポジトリの実際の配置に合わせてください。

> WCAGやJISの達成基準を説明するときは、まず `wcag-jis-data` の `tools/show_criterion.py` で番号を調べる。出力の `edition`、`status`、`source_ref` を確認し、W3C英語原文とWAIC参考訳を区別して回答する。JISの本文やページの適合判定をこのデータセットから推測しない。番号が不明なら名称・本文から候補を探し、候補番号を再照会する。

この指示はAIの参照手順です。データセット自体がページを自動判定するわけではありません。
