# 参照データセット設計案

この案に基づく最初のデータ本体は `data/` に作成済み。収録範囲と未完了事項は[データのREADME](../data/README.md)を参照。

## 目的と境界

WCAGとJIS X 8341-3の項目を版ごとに識別し、原文、日本語名称、適合要件、出典をたどれるようにする。日本語での調査と報告書作成を主な用途とし、JSONを基礎形式にして、CSV、閲覧用HTML、MCPから利用できるようにする。

このデータセットは規格の参照基盤である。個々のウェブページに対する適用可能性、適合・不適合、試験結果は別のデータとして扱う。確認質問や検査手順は拡張層に置き、規格の記述と混同しない。

## 入力資料で網羅したい範囲

手元の `criteria.xlsx` は1シートで、値のある行が117件ある。原則4件、ガイドライン13件、達成基準87件（WCAG 2.2で廃止された4.1.1を含む）、適合に関する項目13件である。列は識別子、英語名、JIS X 8341-3:2016での名称、WCAG 2.0の初期訳と後の訳、WCAG 2.1訳、「新JISでの名称（予定）」の7列である。

`icl.xlsx` には `ICL Template` と `Config` がある。前者には条件見出しと個別の検査項目が混在し、検査項目には複数の達成基準IDが対応することがある。後者は `wcag22`、`AAA` などの設定を含む。これらの内容は、参照データ本体とは別の実務知識として検討する。

## データの分割

| 種類 | 主な項目 | 役割 |
| --- | --- | --- |
| `sources` | 出典ID、文書名、発行主体、版、URL、取得日、利用条件 | すべての値の由来を示す |
| `items` | 項目ID、項目種別、親項目ID、出現する規格版、状態 | 原則・ガイドライン・達成基準・適合要件を識別する |
| `texts` | 項目ID、言語、テキスト種別、本文、出典ID | 規格本文や参考訳を版ごとに保持する |
| `names` | 項目ID、言語、名称、出典ID、名称の位置づけ | 旧訳や予定訳を上書きせず保持する |
| `relations` | 起点の項目、先の項目、関係、根拠 | WCAGとJISの対応を明示する |
| `practice`（後続） | 条件、確認質問、検査手順、関連ID、出典 | 人による試験を支援する |

項目は `standard + edition + item_id` で識別する。たとえば `wcag:2.2:1.1.1` と `jis-x-8341-3:2016:1.1.1` は別の項目とし、対応関係を `relations` に置く。番号が同じだけで本文や適用範囲まで同一とは推定しない。原則、ガイドライン、達成基準、適合要件を `kind` で区別する。

各名称には `source_id` と `status`（正式、参考訳、旧訳、予定、要確認など）を付ける。`criteria.xlsx` の列見出しはそのまま記録できるようにするが、見出しだけで公式の出典や発行日が確定したものとは扱わない。`-`、空欄、「その版に存在しない」も別の状態として管理する。Excelの `5.0` のような数値セルは、元の表示値を確認してから文字列の項目IDに正規化する。

## 正本と版の扱い

- WCAG 2.2の構造と英語本文は、[W3Cの仕様](https://www.w3.org/TR/WCAG22/)と[公式JSON](https://github.com/w3c/wcag/tree/main/11ty/json)から取得する。取得日と取得元の版を固定し、取り込み時に原文を改変しない。
- 日本語訳は[WAICのWCAG 2.2訳](https://waic.jp/translations/WCAG22/)を出典として、取得時点を記録する。訳語が変わっても旧名称を消さない。WAICは2026年6月に複数の訳語を更新している。
- JIS X 8341-3:2016はWCAG 2.0との一致規格として、独立した版で扱う。JIS本文の収録は利用条件を別途確認する。まずは名称、識別子、参照先、明示的な対応関係を対象にする。
- 「新JISでの名称（予定）」は2027年版を想定した予定として保持し、正式なJISの名称と表示しない。原則・ガイドライン・達成基準の接尾語を付けた表示名は元の名称と別に保持する。将来JISが改正された場合も、その版を新しい出典として追加する。
- `4.1.1` は履歴と名称比較のため残し、WCAG 2.2では廃止された状態を明示する。現行の達成基準一覧に混ぜない。

## 公開と再利用

公開部分は、機械可読なJSON、扱いやすいCSV、出典へ移動できるHTMLを生成可能にする。公開用データと、手元の入力資料・評価記録は分ける。`criteria.xlsx` と `icl.xlsx` はGitから除外し、本文の転載や派生データの公開範囲は資料ごとに確認する。

W3Cの[JSON利用条件](https://github.com/w3c/wcag/tree/main/11ty/json#permission-to-use-with-attribution)は出典表示と内容を改変しないことを求める。[WAIC訳の利用条件](https://waic.jp/license-for-translated-documents/)は出典リンク、翻訳者、文書の位置づけ、正式版がW3Cの英語版である旨の表示を求める。公開物では規格由来の文と独自の補足を表示上もデータ上も区別する。

## 最初の実装単位と検証

1. 出典台帳と、原則・ガイドライン・達成基準・適合要件の識別子一覧を作る。
2. `criteria.xlsx` の7列を失わずに取り込める名称モデルを作り、公式出典と照合する。
3. WCAG 2.2の原文とWAIC訳を版付きで追加する。
4. JIS X 8341-3:2016との対応関係を、根拠を添えて追加する。
5. 必要になった時点で `icl.xlsx` の条件見出しと検査項目を分離して追加する。

取り込み時には、項目IDの重複・親子関係・参照先の実在・出典の欠落・廃止状態・名称の欠落理由を検査する。`criteria.xlsx` の117行を出典付きで照合できることを最初の網羅性の確認条件とする。検査件数だけで内容の正確性を保証したことにはしない。
